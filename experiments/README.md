# Experiments

Data-driven benchmark experiments for the traffic signal coordination project.
Everything in this folder is generated by running:

```bash
python -m traffic_coordination.experiments.benchmark_runner --all
```

## Folders

- `configurations/` — JSON configuration of every scenario (A-E main + F/G/H/J
  sensitivity). These files drive the runs; edit them (or
  `src/traffic_coordination/experiments/scenarios.py`) to add scenarios.
- `results/` — `benchmark_results.csv` (row per scenario x algorithm),
  `benchmark_metadata.json` (full configs, seeds, verification outcomes),
  `summary.md` (rendered tables and honest-incomplete notes).
- `figures/` — matplotlib PNG charts generated from the measured results.

## Scenario matrix

| Name | N | Demand (veh/dir @ headway) | Resolution | Progression tolerance | Purpose |
|------|---|---------------------------|------------|----------------------|---------|
| A | 3 | low (10 @ 3 s) | 5 s | none                  | small full-enumeration benchmark |
| B | 5 | medium (20 @ 1 s) | 5 s | none | report's primary illustration scenario |
| C | 7 | medium | 5 s | 10 s | scalability with tractable constraint |
| D | 5 | high (50 @ 1 s) | 5 s | none | oversaturation sensitivity |
| E | 5 | medium | 1 s | 10 s | resolution sensitivity |
| F1-F3 | 5 | low/medium/high | 5 s | none | demand axis |
| G1-G2 | 5 | medium | 5 s / 1 s | 10 s | matched-resolution axis |
| H1-H2 | 5 | medium | 5 s | none | speed axis (30 / 50 km/h) |
| J1-J2 | 5 | medium | 5 s | none | objective-weight axis (beta = 0 / 4) |

All scenarios use seed 42 and the report's defaults (C = 60 s, G = 30 s,
400 m links, 40 km/h where not varied).

## Verification policy

- Exhaustive brute-force verification runs for every scenario whose raw offset
  space is modest; results are recorded in the metadata JSON and summary.
- For scenarios C and E the space is too large; exhaustive verification is
  **skipped and recorded as skipped** — never silently reported as passed.
- When the progression tolerance constraint is active, the verified optimum is
  the optimum *within the constrained space*, which is why those scenarios
  state the constraint in their description.
